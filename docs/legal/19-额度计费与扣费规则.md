# 19 额度、计费与扣费规则

> 版本：v1.0 草案 · 关联：16 定价、17 到账、18 退款、02 服务说明、03 BYOK、30 处置
> **本篇涉及钱怎么算、怎么扣、什么时候停。全部规则在产品内可实时查询。加粗条款请重点阅读。**

## 第一章 计量的基本单位

1.1 本服务的内置模型链路按 **token** 计量。token 是模型处理文本的单位，**大致对应：1 个汉字约 1–2 个 token。**

1.2 一轮对话的消耗由三部分构成：

| 组成 | 说明 | 是否受您控制 |
|---|---|---|
| **输入 token** | 发送给模型的全部内容：角色设定 + 检索到的记忆 + 携带的历史消息 + 您本轮的输入 | **是**（见 §1.3） |
| **输出 token** | 角色回复的长度 | 部分（可设输出偏好） |
| **缓存命中部分** | 与之前请求完全相同的前缀，按更低价格计算 | 由系统自动优化 |

1.3 **关键认知：输入消耗通常远大于输出消耗。** 因为"携带的历史消息"会随对话变长而增加。**这不是隐藏扣费，而是对话型产品的固有结构**，因此我们提供：

（a）每轮实际消耗的实时显示（可关闭）；
（b）携带规模、召回条数、输出长度的自主调节；
（c）"成本优化"面板与"省额度模式"。

1.4 **我们不以"用户看不懂 token"为理由模糊计费。** 产品内同时给出：本轮消耗、剩余金额、按当前速度预计可聊轮数。

## 第二章 价格与折算

2.1 额度以人民币计价。**1 元额度约等于 25 轮典型对话**（按默认携带规模与平均回复长度估算）。

2.2 **这是估算，不是保证。** 实际取决于：您的携带规模设置、角色人设长度、记忆召回条数、回复长度。调高携带规模会显著增加每轮消耗，**产品内会在您调高时明示倍数**。

2.3 单价可能因上游模型价格变化而调整。调整前按 01 号专篇 §5.2 通知不少于 15 日，**且不适用于您已购买的额度**——已购额度按购买时的折算标准消耗完毕，或按 §6.4 处理。

## 第三章 扣费流程（预冻结与结算）

3.1 **每轮对话的扣费分三步，这是为保护双方而设计的流程：**

```
第 1 步  预冻结
        发起请求前，按"本轮最坏情况的估算上限"冻结一笔金额
        若余额不足该上限 → 直接拒绝，不调用模型，不产生任何消耗
第 2 步  生成
        模型流式生成回复，实时累计实际消耗
第 3 步  结算与退回
        生成结束 → 按实际消耗结算，冻结金额与实际金额的差额立即退回您的余额
```

3.2 **为什么用预冻结而不是先扣后算**：若先扣，模型失败时您已付的钱需要走退款流程；若先算后扣，可能扣不到。**预冻结 + 结算**是唯一能让"失败必不退错、成功不多收"的做法。

3.3 **对您账户余额的实际影响：**

| 时点 | 余额显示 |
|---|---|
| 请求发起瞬间 | 可用余额减少（显示为"占用中"） |
| 生成完成 | 按实际消耗扣减，差额回到可用余额 |
| 生成失败 | **全额退回，净变化为零** |

3.4 您可在账单页查看每一笔的冻结、结算、退回记录。**账本为不可变流水，我们技术上无法修改历史账单——这对您也是保护。**

## 第四章 余额耗尽时的行为

4.1 **余额不足时，我们不会让请求进入模型调用**，而是直接提示额度不足并给出续期入口。

4.2 **正在生成时余额耗尽的处理：**

（a）若剩余余额不足以覆盖本轮的估算上限，我们在**发起前**拒绝；
（b）若在生成过程中实际消耗逼近冻结上限，我们会**让当前句子说完后停止**（优雅收尾），而不是在半句话处硬切；
（c）**已生成的部分对应实际消耗，不予退还**——因为该部分成本已实际发生；
（d）停止时明示已消耗金额与余额。

4.3 **我们绝不做的行为：**

（a）不在余额为零时继续调用模型并事后向您追讨；
（b）不通过降低回复质量、缩短回复的方式"偷偷省成本"而不告知；
（c）不将失败请求的成本转嫁给您；
（d）不以"预冻结未结算"为名长期占用您的余额（结算或退回在请求结束时同步完成）。

## 第五章 BYOK 链路的计费

5.1 **BYOK 链路不消耗您的平台额度，我们不从中收费。** 模型费用由您在服务商侧自行支付。

5.2 但请注意：

（a）**记忆检索、嵌入计算、存储、同步、语音合成等能力仍消耗我们的资源**，这些能力按 16 号专篇的档位约束，**我们可能按档位收费，不因您使用 BYOK 而免除**；
（b）语音合成按字符计量，**独立于模型额度单独计算**，产品内分别显示；
（c）我们会在 BYOK 链路下显示本轮的 token 消耗，帮助您核算您在服务商侧的成本，**该数字为估算，以服务商账单为准**。

5.3 我们明示这一点，是为了避免"我用了自己的 Key 为什么还要付会员费"的误解：**您付的是客户端能力（记忆、同步、音色、皮肤），不是模型调用。**

## 第六章 透明与查询

6.1 您可随时查询：

| 内容 | 位置 |
|---|---|
| 当前可用余额与占用中金额 | 全局顶栏 / 额度页 |
| 每轮对话的消耗明细 | 每条回复下方（可关）+ 账单页 |
| 缓存命中情况 | 消耗看板 |
| 按当前速度的预计剩余轮数 | 额度页 |
| 全部冻结/结算/退回流水 | 账单页，可导出 |
| 各档位的额度与价格 | 16 号专篇 + 档位对比页 |

6.2 **我们承诺：任何扣费都可追溯到具体一轮对话。** 不存在"系统调整""服务费""其他费用"这类无对应明细的扣减。

6.3 若出现无对应明细的扣减，**我们主动退回并按 18 号专篇 R8 处理**。

6.4 若单价下调，我们**不追溯调整**已购额度的折算标准（您已按当时价格购买，规则不变）。

## 第七章 计费错误的处理

7.1 下列情形构成计费错误，我们主动纠正：

（a）同一请求产生两条冻结流水；
（b）模型失败但仍扣减了额度；
（c）实际消耗与显示消耗不一致且差异由我们造成；
（d）冻结后未结算也未退回（占用中金额长期不释放）。

7.2 **纠正方式**：即时退回差额；若已造成您的实际损失（例如因余额被错误占用而中断服务），我们补足相应额度。

7.3 我们每日自动核对账本一致性（冻结总额 = 结算 + 退回）。**核对不平即触发人工核查并暂停该账号扣费**，宁可停止服务也不让错账继续。

7.4 您发现疑似计费错误，可通过【联系邮箱】提出（标题"计费"），我们 15 个工作日内答复并说明核查过程。
