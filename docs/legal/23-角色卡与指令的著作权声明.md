# 23 角色卡与指令的著作权声明

> 版本：v1.0 草案 · 关联：20 创作者、22 UGC、24 知识产权、25 审核申诉、30 处置
> **本篇回应社区里一个真实且强烈的情绪：我写的卡被人转走改了几句就当自己的发。**

## 第一章 什么受保护

1.1 **角色卡**（人设描述、世界观设定、示例对话、开场白、行为说明）与**指令**（引导模型行为的提示词文本）属于**文字作品**，符合独创性要求的部分受著作权保护。

1.2 受保护的具体内容：

| 内容 | 是否受保护 | 说明 |
|---|---|---|
| 您撰写的人设描述文字 | **是** | 您的表达，不是想法 |
| 您撰写的示例对话 | **是** | 独创性最高的部分 |
| 您撰写的开场白 | **是** | — |
| 您设计的角色经历、关系设定 | 视表述而定 | 具体到成文字的表达受保护；抽象设定本身不受 |
| 您上传的立绘、头像 | **是**（美术作品），但权利可能属于画师 | 见 §1.3 |
| 角色名字本身 | 通常不受 | 简短名称一般不构成作品 |
| "高冷御姐""温柔学长"这类通用标签 | **不受** | 属于公有领域的常见设定 |
| 通用格式字段（姓名/简介/开场白） | **不受** | 属于通用结构 |

1.3 **重要提醒**：若立绘由他人绘制，**该美术作品的著作权属于画师**，除非您取得了授权。**"我付钱约的稿"不等于自动取得全部权利**——取决于约定。请保留授权依据。

1.4 **不受保护的部分同样可以自由使用。** 我们不会把"某个角色设定很受欢迎"变成某人的垄断。保护的是**表达**，不是**点子**。

## 第二章 署名与来源

2.1 我们提供以下机制保障署名：

（a）角色卡记录**创建者账号**与创建时间；
（b）导入的卡保留**原始来源标记**（若原卡含作者信息）；
（c）社区展示页显示作者署名与"来自 XX 的分享"；
（d）导出时保留作者字段。

2.2 **这些机制是技术辅助，不是权利登记。** 我们能证明"这张卡在我们这里的上传者是某账号"，**但不能证明该账号就是真正的著作权人。**

2.3 因此发生权属争议时，我们按第五章处理，**不充当裁判**。

## 第三章 禁止的转传行为

3.1 **下列行为构成对您社区约定的违反，我们予以处理：**

| 编号 | 行为 | 处理 |
|---|---|---|
| T1 | 将他人卡完整转载并署自己名 | 下架；计入违规（30 号专篇） |
| T2 | 将他人卡改动少量文字后作为原创发布 | 同上（改动不产生新权利，仍属转载） |
| T3 | 将他人**免费公开**的卡作为**付费卡**上架 | 立即下架；终止创作者资格；已收款按 18 号专篇向购买者退款 |
| T4 | 移除原卡中的作者声明、来源标记 | 下架 |
| T5 | 批量搬运外部平台的卡充数 | 限制上架；情节严重终止资格 |

3.2 **关于"禁止二传二改"的效力边界（必须说清楚）：**

（a）作者声明"禁止二传二改"，属于**社区道德约定与许可条件**；
（b）**它不自动产生法律上的强制力**——著作权法保护表达不被复制传播，但"不得修改"这类条件是否有效取决于是否构成许可条款；
（c）**我们的做法是产品机制上支持它**：保留作者声明、保留来源标记、对明显转载行为按下架处理；
（d）**但我们无法控制他人在服务外的行为。** 卡被下载后转发到群、到其他平台，我们无法追回。我们如实说明这一局限。

3.3 **合理的再创作不受本章限制：**

（a）以同一公有领域设定为基础，自己重新写一套人设与示例对话 → **允许**；
（b）在原卡基础上作出实质性、独立的新表达（不是改几个词） → **允许，但建议注明灵感来源**；
（c）为适配自己使用的模型而作的格式转换、字段调整（自用） → **允许**；
（d）评论、分析、引用少量片段进行讨论 → **允许**（合理引用）。

## 第四章 导入外部卡的责任

4.1 本服务支持导入通用格式的角色卡。**导入行为的责任由导入者承担：**

（a）**您应确认您有权导入并使用该卡**（作者允许传播、或为开源许可、或为您自己创作）；
（b）导入后您**不得**将其作为原创公开发布（T1、T2）；
（c）导入的卡默认**仅自己使用**，不进入社区；
（d）若您导入的卡含第三方知识产权（影视、游戏、动漫角色），发布公开时按 §3.1 与 22 号专篇 §3.2 处理。

4.2 导入时我们会：保留原卡中的作者字段与来源信息；**明示哪些字段被丢弃或不支持**（不静默丢失）。

4.3 **我们不主动扫描导入内容以比对其他平台的卡**——这既不可行（无全网索引），也会构成对您上传内容的过度处理。我们依赖举报机制（25 号专篇）。

## 第五章 权属争议的处理

5.1 若您认为某张卡侵犯了您的著作权，或您被指控侵权：

```
提交：产品内"举报 → 版权"入口，或【联系邮箱】（标题"版权"）
需包含：
  ① 您的身份与联系方式
  ② 被指侵权内容的定位（链接/角色名/时间）
  ③ 您的权利依据（创作时间证据、源文件、发表记录、授权链）
  ④ 构成侵权的具体说明（哪些部分、如何对应）
处理：
  · 收到即记录，形式要件齐备后 15 个工作日内答复
  · 期间被指内容可能被暂时隐藏（不是认定侵权，是防止损害扩大）
  · 结果书面告知双方，双方均可申诉
```

5.2 **我们的角色是"通知—转送—必要处置"，不是裁判。** 我们不具备认定著作权归属的能力与权限。

（a）双方证据大致相当且争议明显时，我们可能**维持暂时隐藏并建议双方通过行政或司法途径解决**；
（b）我们**不主动披露对方的身份信息**。若您需追责，请通过执法或司法机关依法定程序要求我们提供（见 15 号专篇 §4.3）。

5.3 申诉：任一方可在收到结论后 15 日内申诉，由不同路径复核，10 个工作日内答复。

5.4 **恶意投诉**（无权利依据、以打击他人为目的的批量举报）：我们计入投诉方违规记录，情节严重的按 30 号专篇处置。

## 第六章 我们自己的立场

6.1 **我们不主张对您上传内容的著作权。** 我们只取得 22 号专篇 §5.1、24 号专篇第四章所述的服务运行所必需的许可。

6.2 **我们不将您的卡用于模型训练**（14 号专篇 §5.2），**不授权任何第三方使用**，**不用于广告**。

6.3 若我们停止服务，我们将提供导出，并在合理期限内保留导出通道（见 04 号专篇 §3.2）。**我们不会在停服后继续分发您的内容。**

6.4 我们鼓励作者使用产品内的"支持作者"位（跳转您自己的收款主页）——**这是社区里"免费分享"与"合理回报"之间最干净的路径**，且不经过我们，没有抽成。
