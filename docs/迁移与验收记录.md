## 四、真跑才暴露出来的问题（静态检查看不见）

| # | 问题 | 严重度 | 修法 |
|---|---|---|---|
| 1 | **两个 `auth.users` 触发器按名字字母序执行**，`trg_user_balance` 早于 `trg_user_created`，导致插 `balances` 时 `profiles` 还不存在 → 外键viol接 | **致命：线上新用户注册直接 500** | 合并为单触发器，内部按 profiles → entitlements → balances 顺序 |
| 2 | `plan_catalog` 的 `credit_valid_days` 走列默认值，年包行在 INSERT 阶段就违反随后要加的约束 | 高：**迁移不可重跑** | 显式给值 + 把加列挪到 insert 之前 |
| 3 | `refresh_balance` 的 INSERT 列 8 个、SELECT 只给 7 个（漏 `user_id`） | 高：调用即报错 | 补 `p_user` |
| 4 | `recall()` 里 `union all` 的列名只取第一分支，外层引用 `kw_score` 报列不存在 | 高：函数创建即失败 | 两分支都补别名 |
| 5 | **`to_tsvector('simple')` 对未分词中文把整句当一个 token**，搜「火锅」匹配不到「用户喜欢吃火锅」；原兜底只有前缀 LIKE，中串同样漏 | 高：**中文记忆功能实际不可用** | 补子串 `ILIKE`，配合已有的 `gin_trgm_ops` 索引 |
| 6 | **列级 `REVOKE` 挡不住 Supabase 的表级 default 授权**，`authenticated` 仍能整行读走 BYOK 密文 blob | 中：信封加密的"密文不可下载"目标落空 | 拆 `byok_secrets` 独立表 + 对前端角色零授权 |
| 7 | 账本 append-only **没有出口**，而 `profiles` 外键是 `restrict` ⇒ 产生过账本的用户永远删不掉，连 postgres 都被自己触发器锁死 | 中：开发/测试数据永久堆积 | 会话级逃生门 `app.ledger_purge='on'` + 强制 `app.purge_reason` |
| 8 | `i1` 不变式定义成 `settle+refund == freeze`，把**在途未结算**的正常冻结判为违规 | 中：对账天天误报 | 改为「释放额不得超过冻结额」+ 新增「同一笔不得结算两次」 |
| 9 | `ssrf.ts` 里非法正则 `/^fd/00/i` | 高：**Edge Function 加载即崩** | 修正则 |
| 10 | `md5` 对孤立代理项的编码与 Node/WHATWG 不一致 | 低（签名场景碰不到，但属实现错误） | 非法定型的代理项编码为 U+FFFD |

## 五、测试工具自身的三个假信号（差点导致误判）

1. **`c.escape()` 已被 node-postgres 移除** → `as()` 每次抛异常 → `denied()` 把"工具崩了"当成"权限被拒"，**一批零读测试是假通过**。修法：工具异常（无 5 位 SQLSTATE）单独抛 `HARNESS FAILURE` 并中止套件。
2. **`denied()` 对 SELECT 的语义用错** → RLS 正常过滤时返回 0 行不报错，却被判成 FAIL。修法：按语句类型分流，SELECT 要求 0 行或报错，DML 要求报错。
3. **`select count(*)` 不能用来判断"是否读到数据"** → RLS 过滤后它仍返回一行（值 0），被误判为泄漏。修法：直接选目标列，按行数判。

> 另外，第一次测 `check-prefix` 时我用 python3 注入，python3 不存在导致注入静默失败，我差点下结论"防线在真实代码上失效"。**反向测试必须断言前提成立。**
