> 上位文档：`docs/HANDOFF.md`（硬约束见其 §3，本文不重复只展开）

## 1. 分层与职责边界

| 层 | 承担 | 绝不承担 |
|---|---|---|
| **网页端**（Vite+React18+TS） | 渲染、输入、本地状态、流式拼接显示、PWA 清单、iOS 适配 | 拼 prompt、持有模型 Key、算钱 |
| **安卓端**（Kotlin+Compose） | 原生渲染、长连接与保活、通知、应用内更新 | 同上 |
| **Edge Function** | 拼静态前缀、解密 BYOK Key、调模型、流式转发、扣费结算、记忆召回、权益发放、推送下发 | 长期持有会话状态（状态在库） |
| **Postgres** | 唯一真源：对话、记忆、账本、社区、权益 | 缓存层（不做应用层缓存表） |
| **Storage** | 立绘、头像、表情包包、APK | 用户敏感导出文件（导出走临时签名链接） |
| **Realtime** | 长连接通道（网页 + 安卓共用） | 消息投递保证（投递保证只认数据库） |

**一句话原则**：*能进数据库的不放缓存，能在 Edge Function 算的不放前端，前端只负责让人看着舒服。*

## 2. Edge Function 接口契约

命名规则：kebab-case，版本前缀留空（一期不做多版本，改接口靠向后兼容）。

### 2.1 `chat` — 对话主链路

**请求**
```jsonc
POST /functions/v1/chat
{
  "session_id": "uuid",
  "character_id": "uuid",
  "content": "用户输入原文",
  "attachments": ["storage-path"],     // 可选，表情包/图片
  "client": "web" | "android" | "ios-webapp",
  "idempotency_key": "uuid"            // 防重复扣费，客户端生成
}
```

**响应**：`text/event-stream`（SSE）
```
event: meta      data: {"message_id":"...","frozen_amount":"0.0312","model":"deepseek-flash","cache_hit":true,"carried_tokens":8142}
event: delta     data: {"t":"你"}
event: delta     data: {"t":"今"}
...
event: done      data: {"message_id":"...","usage":{"prompt":8142,"completion":604,"cached":3072},"settled":"0.0035","balance":"12.88"}
event: error     data: {"code":"INSUFFICIENT_BALANCE","msg":"..."}
```

**关键行为**
1. 收到请求 → 校验权益与余额 → **预冻结**（写 `ledger` 一条 `type='freeze'`）
2. 拼 prompt（顺序见 §4）
3. 调模型，流式转发
4. 结束 → **结算**（写 `type='settle'`，差额写 `type='refund'`）
5. 失败 → 全额退回（`type='refund'`，`reason='model_error'`）
6. 落 `messages` 表（用户消息在冻结后立即落，AI 消息在流结束后落，中途断则落已生成部分并标 `partial=true`）

**错误码约定**
| code | 含义 | 客户端行为 |
|---|---|---|
| `INSUFFICIENT_BALANCE` | 余额不足 | 弹充值引导（不写"续费"字样，见 D1） |
| `RATE_LIMITED` | 平台侧限频 | 静默重试 1 次后提示 |
| `MODEL_TIMEOUT` | 上游超时 | 静默重试 2 次，指数退避 |
| `MODEL_STREAM_BREAK` | 流中断 | 保留已输出 + 显示"继续"按钮 |
| `QUOTA_EXCEEDED` | 超出档位携带量/召回数 | 提示升档 |
| `ROLE_LOCK_VIOLATION` | 内部：输出校验判定出戏 | 静默重生成，不告知用户 |

**BYOK 分支**：请求体加 `"provider": {"kind":"openai"|"anthropic", "profile_id":"uuid"}`。`profile_id` 指向库里加密存的 Key，Edge Function 解密后直连用户 endpoint，**该轮不扣平台额度**（但仍记 `ledger` 一条 `type='byok_usage'`，amount=0，用于统计与反滥用）。

> ⚠️ 注意：BYOK 也走 Edge Function 代发。这是 C8/G1 的必然结果——用户 E5 选了"Key 云端托管多端同步"，那 Key 就只能出服务端。副作用是 BYOK 用户也要吃一跳延迟，文案上需说明"为保护你的密钥，请求经服务器中转"。

### 2.2 `deduct` — 账本读写

只暴露两个动作：`balance`（查余额与流水）与 `pack_purchase`（加量包到账确认）。**扣费永远由 `chat` 内部完成，不单独暴露扣费接口**——避免客户端能绕过对话直接扣钱或被伪造。

### 2.3 `recall` — 记忆检索

```jsonc
POST /functions/v1/recall
{ "character_id":"uuid", "query":"...", "top_k":8 }
→ { "items":[{"id","kind":"vector"|"keyword"|"fact","text","score","source_msg_ids":[]}] }
```
`top_k` 上限由档位决定（§4.4 矩阵），超出直接截断到档位值，不报错。

### 2.4 `afdian-hook` — 爱发电订单比对与自动发放

```jsonc
POST /functions/v1/afdian-hook
{ "event": "order.paid" | "query", "afdian_user_id":"...", "order_id":"..." }
```
内部逻辑（幂等，靠 `orders.external_id` 唯一约束）：
1. 用爱发电 API 拉该 `afdian_user_id` 的订单列表
2. 与 `plan_catalog`（我们侧的商品映射表）比对，识别档位
3. 命中 → 写 `orders` + 写 `entitlements`（有效期 +31 天或 +372 天）+ 写 `ledger`（`type='grant'`）
4. 未命中 → 落 `unmatched_orders` 待人工在后台看（**不通知用户、不弹客服**，符合"我不找客服"）

**触发方式**：优先轮询（定时 `edge` cron 每 60s 拉增量订单），因为爱发电 webhook 可用性【待确认，见 HANDOFF 附录 B Q3】。轮询与 webhook 走同一套幂等逻辑，可并存。

### 2.5 `push` — 主动关怀与推送下发

```jsonc
POST /functions/v1/push   // 内部调用（cron 触发）
{ "kind":"care"|"reply"|"system", "character_id":"...", "user_id":"..." }
```
行为：**先落 `messages`（role='assistant', origin='proactive'）**，再尝试推送通道。推送失败不影响消息存在。客户端打开时通过 `GET /messages?since=<last_seen_at>` 补发。

### 2.6 `export` / `erase` — 数据出口

- `export` → 生成 JSON（对话、角色、记忆、账本）+ CCv2 角色卡，写 Storage 私有桶，返回 10 分钟签名链接
- `erase` → 二次确认后级联删除：`messages`、`memories`（含向量）、`facts`、`character_sessions`、`balances`（余额须先为 0 或走退款）、`auth.users`。`ledger` 保留但做匿名化（`user_id` 置 hash），因为财务凭证有留存必要。

### 2.7 `version` — 版本清单（网页与安卓共用）

```jsonc
GET /functions/v1/version
→ {
  "web":     { "build":"20260926.3", "notes":"...", "force_refresh":false },
  "android": { "version_name":"0.3.1", "version_code":31, "url":"...apk", "sha256":"...", "size":18432000, "min_version_code":28 },
  "ios_hint":{ "added_to_home":true }
}
```
一个接口喂三端。安卓据此走应用内更新；网页据此让 SW 弹"有新版本，点击刷新"（**只提示，不缓存**，符合 B4）。

## 3. 数据库 schema 总览

命名：表名复数 snake_case，时间统一 `timestamptz`，金额统一 `numeric(12,4)`（**不用 float，钱不能是浮点**）。

### 3.1 用户与权益
```
users                 扩展资料（挂 auth.users 上）
plan_catalog          商品映射：afdian 商品 → 档位 → 有效期天数 → 额度
entitlements          用户当前权益：tier, expires_at, granted_days
balances              余额快照（派生值，可由 ledger 重算校验）
orders                爱发电订单落地：external_id 唯一
unmatched_orders      比对失败的订单，仅后台可见
```

### 3.2 账本（★不可变）
```
ledger
  id, user_id, type, amount, balance_after(冗余，可校验),
  ref_kind, ref_id, request_id(幂等键), reason, created_at
  -- 仅 INSERT，禁止 UPDATE/DELETE（RLS + 触发器双重锁）
```
`type` 枚举：`freeze` / `settle` / `refund` / `grant` / `purchase` / `byok_usage` / `adjust`

余额 = `SUM(grant) + SUM(purchase) - SUM(settle) - SUM(adjust_out)`，冻结未结算部分单独聚合为"占用中"。
> 这条聚合查询必须做物化视图或生成列，否则每次查余额全表扫。见分册-后端 §账本。

### 3.3 角色与对话
```
characters            角色卡主体（含扩展字段 + CCv2 兼容层）
character_versions    人设变更历史（改人设不能影响已发生的记忆）
character_locks       ★隐藏锁 prompt（RLS：用户侧完全不可读，仅 service_role 可读）
sessions              会话（一个用户 × 一个角色 × 可选群聊）
session_members       群聊成员（单聊也走这张表，便于二期无缝扩）
messages              消息真源：role, content, origin(user|assistant|proactive|system),
                      partial, usage_prompt, usage_completion, usage_cached, cost_actual
memories              ★向量 + tsvector：kind(fact|episode|summary), text, embedding vector(1024),
                      source_msg_ids, character_id, user_id, salience, last_recalled_at
memory_links          记忆与消息的溯源关系（导出与删除要能级联）
affinity_state        内层好感度数值（★用户侧不可读）
relationship_stage    外层关系阶段（用户侧可读）
```

### 3.4 社区
```
posts / comments / reactions        广场、评论、分享流
shares                            分享图记录（用于统计传播）
card_listings                   二期卖卡：定价、抽成、创作者收款页
creator_earnings                二期分成记账
```

### 3.5 运营
```
sensitive_rules          拦截规则库（后台可维护）
admin_audit              后台操作留痕
announcements            公告
push_devices             设备与推送 token（网页 subscription / 安卓长连接 client_id）
proactive_jobs           主动关怀任务队列（含状态：pending/sent/skipped）
```

**RLS 三条铁律**
1. `character_locks`、`affinity_state` 对 `authenticated` 角色**零读权限**（连 owner 都不行），只有 `service_role` 可读。这是 C8 的数据库层兜底。
2. `messages` / `memories` 按 `user_id` 隔离，社区表按 `visibility` 控制。
3. `ledger` 对 `authenticated` 只读不写，写入只允许经 Edge Function（`service_role`）。

## 4. Prompt 组装顺序（★决定成本，必须逐字遵守）

```
┌──────────────────────────────────────────────────────────┐
│ [静态前缀 A] 平台层锁                       ← 全局唯一，永不变 │
│ [静态前缀 B] 角色锁（人设+示例对话+禁止元讨论）  ← 角色发布后冻结 │
├──────────────────────────────────────────────────────────┤
│ [半静态段]  关系阶段描述 + 好感度摘要         ← 阶段变化才变    │
│ [动态段 1]  RAG 召回片段（top_k 条）                        │
│ [动态段 2]  携带的历史消息（按档位 token 上限截断）           │
│ [动态段 3]  本轮用户输入 + 时间戳 + 余额提示                 │
└──────────────────────────────────────────────────────────┘
   ↑ 缓存命中范围 = 前缀 A + B（+ 阶段未变时的半静态段）
```

**规则**
1. **时间戳、用户名、余额、nonce 一律进动态段末尾**。任何把它们前移的改动都会击穿缓存（HANDOFF §7.2，成本差 3.2 倍）。
2. 角色**发布后**人设文本冻结；要改人设 → 写 `character_versions` 新记录，旧会话的历史不重写。
3. 半静态段只在**关系阶段跃迁**时变化。好感度数值变化**不进 prompt**，只影响阶段枚举 → 一天最多变一次，缓存友好。
4. 静态前缀模板存 `supabase/functions/_shared/prefix/` 独立文件，构建期校验：**禁止在模板里做字符串拼接**。建议加 lint 规则，命中即 CI 失败。

## 5. 核心链路时序

### 5.1 一次对话（内置模型）
```
客户端            Edge chat          Postgres           DeepSeek
  │  POST /chat       │                  │                 │
  │──────────────────▶│                  │                 │
  │                   │ 校验权益/余额      │                 │
  │                   │─────────────────▶│                 │
  │                   │  freeze 写账本    │                 │
  │                   │─────────────────▶│                 │
  │                   │  落用户消息        │                 │
  │                   │─────────────────▶│                 │
  │                   │  recall（并行）    │                 │
  │                   │─────────────────▶│                 │
  │                   │◀─────────────────│                 │
  │                   │ 拼 prompt（§4）    │                 │
  │                   │──────────────────────────────────▶ │
  │◀── SSE meta ──────│◀───────────────────────────────── │
  │◀── SSE delta ─────│        （流式转发，不落库）          │
  │◀── SSE done ──────│ 落 AI 消息 + settle + refund 差额   │
  │                   │─────────────────▶│                 │
  │                   │ 异步：抽取记忆候选（不阻塞响应）      │
```
**延迟预算**：首字节 ≤ 800ms（含冷启动）。若冷启动占大头 → 上 warm 保活（定时自调用）。

### 5.2 主动关怀
```
cron(每5min) → 扫 proactive_jobs 到期 → 生成消息 → 落 messages
  → 查 push_devices → 发 Web Push / 经 Realtime 下发安卓
  → 失败不重投（消息已在库，客户端打开补发）
```

### 5.3 爱发电到账
```
用户付款 → 轮询任务(60s) → 爱发电 API 拉订单 → 比对 plan_catalog
  → 写 orders + entitlements + ledger(grant)
  → 客户端下次拉 /balance 或 Realtime 订阅 entitlements 变更即感知
```
用户侧感知：**无跳转、无兑换码、无客服**。文案只写"已到账"。

## 6. 阶段任务分解

> 只标依赖与出口判据，不标时间（F1 定案）。

### P0 地基
| 任务 | 依赖 | 出口判据 |
|---|---|---|
| 仓库骨架 + `.gitignore`（含密钥文件排除） | — | `git status` 干净，无 token 文件被跟踪 |
| `manifest.json` 单一版本清单落地 | — | 网页与安卓构建脚本都从它读取（各端字段独立，E4） |
| Supabase 项目初始化 + 迁移编号规范 | — | `migrations/001_*.sql` 可重复执行（幂等） |
| CI：push → 构建 web → 发 GitHub Pages | 骨架 | 手机浏览器能打开线上地址 |
| Auth：邮箱验证码 + 爱发电 OAuth（若可用，否则先邮箱） | Supabase | 两条链路各自能登录 |
| 设计 token 基线（颜色/字号/间距/圆角/动效曲线） | — | token 文件被组件消费，无硬编码色值 |

### P1 对话内核
| 任务 | 依赖 | 出口判据 |
|---|---|---|
| `characters` / `sessions` / `messages` 表 + RLS | P0 | 越权读他人会话被拒（写测试） |
| 静态前缀模板文件 + 构建期 lint | P0 | 往模板里拼字符串 → CI 失败 |
| Edge `chat` 流式链路 | P1 表 | 连续 50 轮不崩、不断流 |
| 角色卡数据结构（自定义扩展 + CCv2 字段映射预留） | P1 表 | 序列化/反序列化往返无损 |
| 官方角色 3 个（先能跑，全量待 Q2） | P1 角色卡 | — |
| 极简建卡向导（3 句话建角色） | P1 | 新用户不看说明能建成 |
| 流式 UI（打字机 + 中断保留 + "继续"按钮） | P1 chat | 断网重连不丢已生成文本 |

### P2 成本闭环
| 任务 | 依赖 | 出口判据 |
|---|---|---|
| DeepSeek Flash 接入 + usage 回传解析 | P1 | usage 字段与官网账单对得上 |
| **缓存命中率实测与看板** | P2 接入 | 静态前缀命中率 ≥ 90%（低于此值说明 §4 被破坏） |
| `ledger` 表 + 不可变触发器 + 行锁 | P0 | 尝试 UPDATE → 报错 |
| 预冻结/结算/退回三态 | P2 ledger | 并发 50 请求不超付、不丢钱 |
| `idempotency_key` 防重扣 | P2 | 同 key 重放不产生两条扣费 |
| 携带量分档截断 | P1 | 各档实际 token 不越界 |
| 消耗可视化（本轮花了/省了多少、缓存命中） | P2 | 用户能看懂，且成为卖点文案 |
| 余额到 0 立即掐断 + 优雅收尾 | P2 | 实测欠付 = 0 |

### P3 记忆
| 任务 | 依赖 | 出口判据 |
|---|---|---|
| pgvector 扩展 + `memories` 表 + HNSW 索引 | P2 | 10 万向量下召回 P95 < 80ms |
| tsvector 列 + 触发器维护 | P3 | 关键词检索能命中人名/日期 |
| 混合检索打分融合（`recall` 函数） | P3 | 同一 query 下优于纯向量的基线对比 |
| 记忆抽取（对话后异步） | P3 | 抽取出的事实人工抽检准确率达标 |
| 召回注入 prompt（动态段 1） | P3 + §4 | 不击穿缓存（命中率仍 ≥ 90%） |
| 召回条数分档 | P3 | 免费档 top_k=4 生效 |
| 溯源 `memory_links` + 删除级联 | P3 | 删一条消息，相关记忆同步失效 |

### P4 角色锁定与养成
| 任务 | 依赖 | 出口判据 |
|---|---|---|
| `character_locks` 表 + RLS 零读 | P1 | 用户身份任何查询均被拒 |
| 防漂移拉回（检测到出戏 → 固定句式纠正） | P1 | 诱导测试集通过 |
| 输出校验 + 静默重生成 | P4 拉回 | 用户无感，重生成率有看板 |
| **100 条诱导回归测试集** | P4 | 改任何 prompt 必跑，通过率不得下降 |
| `affinity_state` 内层数值（不可读） | P3 | RLS 拒读验证 |
| `relationship_stage` 外层阶段（可读） | P4 数值 | 阶段跃迁文案正确 |
| 群聊（`session_members`，一期即做） | P1 | 4 人同场不串人设 |

> 群聊成本提醒：N 个角色同场 = N 倍 token。§4.4 里群聊人数上限（2/3/4/6/8）必须与携带量分层一起核算，见 Q5。

### P5 多端与推送
| 任务 | 依赖 | 出口判据 |
|---|---|---|
| iOS WebApp 适配清单全过 | P1 | 见分册-网页 §iOS，真机矩阵逐条 |
| PWA 清单 + 图标 + 主题色 + 启动图 | P0 | 主屏图标正确、无白闪 |

## 7. 跨端一致性契约

网页与安卓**共用同一套 Edge Function 接口与同一份数据库**，因此：

1. 业务规则一律在服务端。客户端只做显示，不做判断（否则两端必然漂移）。
2. 角色卡、权益矩阵、阶段枚举 → 由 `web/src/types/` 单一 TS 源生成一份 JSON schema，安卓侧用脚本生成 Kotlin data class。**契约文件放 `shared/`，两端各有生成器**。
3. 任何"安卓能做而网页做不到"的功能，必须在文档里显式标注为端能力差异，不许静默分叉。当前已知差异：
   | 能力 | 网页 | iOS 主屏 | 安卓 | PC |
   |---|---|---|---|---|
   | Web Push（后台） | ✅ | ⚠️ 需加主屏，送达不保证 | —（用原生） | ✅ |
   | 原生通知 | — | — | ✅ | — |
   | 后台常驻 | ❌ | ❌ | ✅（保活有限） | ✅ |
   | 应用内更新 | 刷新提示 | 刷新提示 | ✅ | 刷新提示 |
   | 文件系统导出 | ✅ | ⚠️ 走分享面板 | ✅ | ✅ |
   | 本地 TTS 播放 | ✅ | ✅ | ✅ | ✅ |

## 8. 密钥与环境变量

**服务端（Supabase Secrets，绝不进前端）**
```
DEEPSEEK_API_KEY          内置模型
AFDIAN_USER_ID / TOKEN    爱发电 API
VAPID_PUBLIC / PRIVATE    Web Push
BYOK_MASTER_KEY           信封加密主密钥（用于加解密用户 Key）
```

**前端可暴露**
```
VITE_SUPABASE_URL / ANON_KEY     公开键，靠 RLS 兜底
VITE_APP_BUILD                   构建号（来自 manifest）
```

**用户 BYOK Key 的存法**
- 信封加密：`BYOK_MASTER_KEY` 加密数据密钥，数据密钥加密用户 Key，密文存 `byok_profiles.encrypted_key`
- 只在 Edge Function 内解密，解密后的明文**不落日志、不进错误信息、不返回客户端**
- 客户端只看到掩码 `sk-****abcd`

**仓库纪律**
- `.gitignore` 必须排除：`*.token`、`*-key.txt`、`supabase/.temp/`、`.env*`（保留 `.env.example`）
- 【必做】首次 commit 前跑一次 `git ls-files | grep -iE "token|key|secret"` 确认无泄漏（尚贤圈那次检查就是这么做的，结论干净）

## 9. 已知架构风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| Edge Function 冷启动拖慢首字节 | 首次对话体验差 → 直接打击北极星指标 | warm 保活（定时自调用）；新用户首次进入预连接 |
| 静态前缀被无意破坏 → 缓存击穿 | 成本涨 3.2 倍，且**不会报错**，只会悄悄亏钱 | §4 规则 4 的构建期 lint + P2 缓存命中率看板 |
| 国产 ROM 杀后台 → 推送收不到 | "主动关怀"卖点失效 | 双层设计（§5.2）：落库为真源，打开补发 |
| 群聊 token 成本 = N 倍 | 重度群聊用户毛利转负 | 人数上限分档 + 群聊单独携带量策略（Q5 待定） |
| 爱发电 OAuth 可能不开放 | D5 归因方案需回退 | 备选：邮箱匹配（用户在爱发电留的邮箱 ↔ 我们注册的邮箱），成功率低但可用 |
| 余额聚合查询全表扫 | 高并发下查余额变慢 | 生成列或物化视图；`balances` 作为派生快照定期校准 |
| 硬删除与财务凭证留存冲突 | 注销后无法对账 | `ledger` 匿名化保留而非删除（§2.6） |
