## 2. 迁移规范（★含一条用血换来的教训）

```
supabase/migrations/
  001_extensions.sql
  002_core_tables.sql
  003_ledger.sql
  004_rls.sql
  005_memory.sql
  ...
```

**规则**
1. 编号三位递增，**只追加不改历史文件**。要改已上线结构 → 新文件写 `alter`。
2. 每个文件**幂等**：`create table if not exists`、`create or replace function`、`drop policy if exists` 后再 `create policy`、`alter table ... drop constraint if exists` 后再加。
3. 每个文件末尾带**自检查询**（返回若干 `_ok` 布尔列），执行后一眼看出是否成功。这是尚贤圈 `010/011` 那轮验证形成的习惯。
4. 回滚脚本单独放 `supabase/rollback/NNN_*.sql`。

### ⚠️ 美元引用（dollar-quote）陷阱 —— 尚贤圈真实事故，必须防

尚贤圈曾连续两轮"假修复"：用 JS 的 `String.prototype.replace` 生成 SQL 时，替换串里的 **`$$` 被当作特殊序列转义成了 `$`**，导致函数闭合端 `end $$;` 被截成 `end $;`，SQL 静默损坏。表面看脚本跑通了，实际函数没建。

**本项目的强制防线**（写进 CI，不许靠人记住）：
```js
// scripts/check-sql.mjs —— 每次迁移前必跑，CI 硬失败
// 校验项：
//  1. 每个 .sql 里 $$ 出现次数必须为偶数（配平）
//  2. 不存在孤立的单个 $ 后接分号（`end $;` 这类截断特征）
//  3. 每个 create function 都有对应的 language/plpgsql 或 returns 子句
//  4. create or replace function 后紧跟 set search_path（防 search_path 注入）
```
另外：**生成 SQL 时如果用 JS 替换，一律用函数式替换** `s.replace(re, () => sql)`，不用字符串替换。这条写进 `AGENTS.md` 级别的约定。

### 4.1 禁止改写（触发器 + 权限双锁）
```sql
create or replace function public.guard_ledger_immutable()
returns trigger language plpgsql set search_path = pg_catalog, public as $fn$
begin
  raise exception 'ledger is append-only';
end;
$fn$;

create trigger trg_ledger_no_update before update on public.ledger
  for each row execute function public.guard_ledger_immutable();
create trigger trg_ledger_no_delete before delete on public.ledger
  for each row execute function public.guard_ledger_immutable();

revoke update, delete, truncate on public.ledger from authenticated, anon;
```

### 4.2 余额派生（不要每查一次全表扫）
```sql
create or replace function public.credit_of(p_user uuid)
returns table (available numeric, frozen numeric, total_granted numeric, total_spent numeric)
language sql stable set search_path = pg_catalog, public as $fn$
  select
    coalesce(sum(case when type in ('grant','purchase','refund') then amount
                      when type = 'settle' then -amount
                      when type = 'adjust' then amount end), 0)                        as available,
    coalesce(sum(case when type='freeze' then amount end)
           - sum(case when type in ('settle','refund') and ref_kind='freeze' then amount end), 0) as frozen,
    coalesce(sum(case when type in ('grant','purchase') then amount end), 0)           as total_granted,
    coalesce(sum(case when type='settle' then amount end), 0)                          as total_spent
  from public.ledger where user_id = p_user;
$fn$;
```
> ⚠️ 上面对 `freeze/settle/refund` 的配对逻辑要求：结算与退回必须回填 `ref_kind='freeze'` + `ref_id=<冻结流水 id>`。写 `chat` 函数时漏了这个，冻结就会永久占用余额。**这条必须进验收清单。**

高频查询走物化视图：
```sql
create materialized view if not exists public.mv_balances as
  select user_id,
         sum(case when type in ('grant','purchase','refund') then amount
                  when type='settle' then -amount
                  when type='adjust' then amount end) as available
  from public.ledger group by user_id;
create unique index on public.mv_balances(user_id);
-- 由 Edge Function 在结算后 refresh 单行（或用 trigger 维护 balances 表），
-- 并每日全量 refresh + 校验 available 与 balances 表一致（对账）
```

### 4.3 预冻结 / 结算 / 退回（行锁 + 幂等）
```sql
create or replace function public.freeze_credit(
  p_user uuid, p_amount numeric, p_request uuid
) returns jsonb language plpgsql volatile set search_path = pg_catalog, public as $fn$
declare
  v_avail numeric; v_row public.ledger%rowtype;
begin
  -- 幂等：同 request_id 已冻结则直接返回既有结果
  select * into v_row from public.ledger
    where request_id = p_request and type = 'freeze' limit 1;
  if found then return jsonb_build_object('ok', true, 'replay', true, 'ledger_id', v_row.id); end if;

  perform 1 from public.profiles where id = p_user for update;   -- ★ 用户级行锁，串行化同用户扣费
  select available into v_avail from public.mv_balances where user_id = p_user;
  if v_avail is null or v_avail < p_amount then
    return jsonb_build_object('ok', false, 'code', 'INSUFFICIENT_BALANCE', 'avail', coalesce(v_avail,0));
  end if;

  insert into public.ledger(user_id, type, amount, request_id)
    values (p_user, 'freeze', p_amount, p_request) returning * into v_row;
  return jsonb_build_object('ok', true, 'ledger_id', v_row.id, 'replay', false);
end;
$fn$;
```
`settle_credit(p_user, p_freeze_id, p_actual, p_request)` 与 `refund_credit(...)` 同构：先 `select ... for update` 锁住那条 freeze 流水，确认未结算，再写 `settle`/`refund` 并回填 `ref_kind='freeze'`、`ref_id=p_freeze_id`。

**并发正确性论证**（写下来防止后人"优化"掉行锁）：
- 同一用户的并发请求在 `profiles` 行锁上串行化 → 不会双双通过余额检查
- `uq_ledger_idem` 保证重试不产生第二条冻结
- 结算只认 `freeze` 流水 id → 不会重复结算同一轮

## 5. RLS 策略

```sql
-- 004_rls.sql
alter table public.messages          enable row level security;
alter table public.sessions          enable row level security;
alter table public.ledger            enable row level security;
alter table public.character_locks   enable row level security;
alter table public.affinity_state    enable row level security;
-- ... 其余同理

-- 5.1 自己的数据
create policy p_msg_own_read on public.messages for select
  to authenticated using (user_id = auth.uid());
create policy p_msg_own_write on public.messages for insert
  to authenticated with check (user_id = auth.uid());
-- ★ 注意：不给 authenticated 的 update/delete。删除走 export/erase RPC（服务端受控）

-- 5.2 隐藏锁：零读（连 owner 都不行）
create policy p_lock_deny_all on public.character_locks for select
  to authenticated using (false);
-- 不写 insert/update policy → authenticated 无法写；只有 service_role 绕过 RLS

-- 5.3 内层好感度：零读
create policy p_affinity_deny_all on public.affinity_state for select
  to authenticated using (false);

-- 5.4 账本：只读
create policy p_ledger_read on public.ledger for select
  to authenticated using (user_id = auth.uid());
-- 无 insert/update/delete policy → 写入只能经 Edge Function（service_role）

-- 5.5 角色：官方公开，私有仅 owner，公开卡走社区审核
create policy p_char_read on public.characters for select
  to authenticated using (
    owner_id is null
    or owner_id = auth.uid()
    or (visibility = 'public' and exists (
         select 1 from public.card_reviews r
         where r.character_id = characters.id and r.status = 'approved'))
  );

-- 5.6 社区内容：公开读、作者可写、举报走 RPC
```

【必做】写一组 RLS 越权测试（架构 §6 P1 出口判据）：用 A 的 token 读 B 的 `messages/sessions/character_locks/affinity_state/ledger`，**必须全部被拒**。`character_locks` 与 `affinity_state` 要额外测"作为角色 owner 也读不到"。

### 6.1 混合检索 RPC
```sql
create or replace function public.recall(
  p_user uuid, p_char uuid, p_query text,
  p_vec vector(1024), p_topk int default 8
) returns table (
  id uuid, kind mem_kind, text text,
  score numeric, vec_score numeric, kw_score numeric, source_msg_ids uuid[]
) language sql stable set search_path = pg_catalog, public as $fn$
  with v as (
    select m.id, m.kind, m.text, m.source_msg_ids,
           1 - (m.embedding <=> p_vec) as vec_score
    from public.memories m
    where m.user_id = p_user and m.character_id = p_char
      and m.invalidated_at is null and m.embedding is not null
    order by m.embedding <=> p_vec
    limit p_topk * 4                                   -- 先过量召回
  ),
  k as (
    select m.id, m.kind, m.text, m.source_msg_ids,
           ts_rank(m.tsv, websearch_to_tsquery('simple', p_query))
           + similarity(lower(m.text), lower(p_query)) * 0.3 as kw_score
    from public.memories m
    where m.user_id = p_user and m.character_id = p_char
      and m.invalidated_at is null
      and (m.tsv @@ websearch_to_tsquery('simple', p_query)
           or lower(m.text) like lower(p_query) || '%')
    limit p_topk * 4
  ),
  u as (
    select id, kind, text, source_msg_ids,
           max(vec_score) as vec_score, max(kw_score) as kw_score
    from ( select id,kind,text,source_msg_ids, vec_score, null::numeric from v
           union all
           select id,kind,text,source_msg_ids, null::numeric, kw_score    from k ) t
    group by id, kind, text, source_msg_ids
  )
  select id, kind, text,
         round((coalesce(vec_score,0) * 0.65
              + coalesce(kw_score,0)  * 0.35
              + salience_bonus(kind, salience, last_recalled_at))::numeric, 4) as score,
         coalesce(vec_score,0), coalesce(kw_score,0), source_msg_ids
  from u
  order by score desc
  limit p_topk;
$fn$;
```
`salience_bonus(kind, salience, last_recalled_at)`：`fact` 类加权（人名/日期/约定必须优先）、近期被召回过的轻微加权。**权重 0.65/0.35 是起点，必须用 100 条标注查询做调参，不许拍脑袋定死。**

### 6.2 记忆抽取（异步，不阻塞对话）
```
Edge chat 流结束 → 投队 extract_jobs
  → 每 8 轮或会话空闲 30s 触发一次
  → 用小模型抽取 {kind:'fact', text, salience} 与 {kind:'episode', text}
  → embedding 批量算（省调用次数）
  → 与既有记忆做近重复检测（vec 相似度 > 0.92 则合并，不新增）
```
每 20 轮生成一条 `summary`，但**summary 不进 prompt**（本项目靠 RAG 召回而非摘要携带，见架构 §7.3）；summary 只用于"记忆回顾"UI 与长期归档。

## 7. Storage 桶

| 桶 | 公开 | 内容 | 大小/格式限制 |
|---|---|---|---|
| `assets` | 公 | 官方立绘、皮肤预览 | ≤ 2MB，webp/png |
| `user-media` | 私（签名 URL） | 用户头像、自建立绘、表情包 | ≤ 5MB，jpg/png/gif/webp |
| `share-out` | 公（7 天） | 分享图生成结果 | ≤ 3MB |
| `apk` | 公 | 安卓包 | 不限 |
| `export-tmp` | 私（10 分钟签名） | 导出文件 | 自动 1 天清理 |

【必做】上传校验**在服务端做**（MIME 用 magic bytes 判，不信扩展名、不信客户端声明的 content-type）。图片一律过一遍重编码，剥掉 EXIF（含 GPS）再存。

```sql
create or replace function public.erase_account(p_user uuid, p_confirm text)
returns void language plpgsql security definer set search_path = pg_catalog, public as $fn$
begin
  if auth.uid() is distinct from p_user then raise exception 'forbidden'; end if;
  if p_confirm <> 'ERASE' then raise exception 'confirm required'; end if;

  delete from public.memories      where user_id = p_user;   -- 向量随行走
  delete from public.messages      where user_id = p_user;
  delete from public.sessions      where user_id = p_user;
  delete from public.characters    where owner_id = p_user;
  delete from public.entitlements  where user_id = p_user;
  delete from public.push_devices  where user_id = p_user;
  delete from public.byok_profiles where user_id = p_user;   -- Key 密文必须删

  update public.ledger set user_id = public.hash_for_retention(p_user)  -- ★ 匿名化保留
   where user_id = p_user;

  delete from auth.users where id = p_user;
end;
$fn$;
```
**为什么 `ledger` 不删**：财务凭证留存与"被遗忘"的冲突，用匿名化解决（架构 §9 最后一条）。导出里给用户的账本副本用原 `user_id`，删除后其无法再关联到人。

`security definer` 的函数必须**显式 `set search_path`**（否则是提权漏洞）。这条也进 CI 检查（§2 规则 4）。

## 9. 索引与性能基线

| 查询 | 目标 | 依赖 |
|---|---|---|
| 会话消息分页 | P95 < 30ms | `idx_msg_session_time` |
| 向量召回 8 条 | P95 < 80ms | HNSW（`ef_search` 会话级设 40） |
| 混合召回 | P95 < 120ms | GIN(tsv) + GIN(trgm) |
| 余额查询 | P95 < 10ms | `mv_balances` 唯一索引 |
| 主动关怀队列扫描 | P95 < 50ms | `proactive_jobs(due_at, status)` 部分索引 |

【必做】上线前造 10 万向量 + 50 万消息的测试数据跑一遍，**不要在生产第一次遇到真实数据量**。

## 10. 备份与运维

- 每日 `pg_dump` → Storage 私有桶，保留 30 天；每周全量快照保留 12 周
- 【必做】**每季度做一次真实恢复演练**（备份没验证过恢复就等于没有）
- 慢查询：`pg_stat_statements` 开，每周看 top 20
- Supabase 配额告警：连接数、存储、出流量三条线设阈值
- 对账任务：每日校验 `mv_balances` 与 `ledger` 重算值一致，不一致告警（这是账本正确性的最后防线）
