```

│  ├─ apple-icons/                # 152/167/180（iOS 主屏必需）
│  └─ fonts/                      # 自托管子集化字体
├─ src/
│  ├─ app/                        # 应用外壳、路由、Provider
│  ├─ features/
│  │  ├─ chat/                    # 对话主界面、流式渲染、输入区
│  │  ├─ character/               # 角色详情、建卡向导、人设编辑
│  │  ├─ memory/                  # 记忆查看与溯源
│  │  ├─ byok/                    # Key 配置与 provider 选择
│  │  ├─ billing/                 # 额度、档位、加量包、消耗看板
│  │  ├─ community/               # 广场、评论、分享流
│  │  ├─ share-image/             # 分享图生成器
│  │  └─ settings/                # 含导出/注销
│  ├─ ui/                         # 无业务的基础组件（按 token 消费）
│  ├─ styles/
│  │  ├─ tokens/                  # design.ts / themes/*.css
│  │  ├─ base.css                 # reset + 全局
│  │  └─ motion.css               # 动效曲线与时长变量
│  ├─ lib/
│  │  ├─ sse.ts                   # 流式解析（含断线续接）
│  │  ├─ push.ts                  # VAPID 订阅管理
│  │  ├─ idempotency.ts           # 客户端幂等键生成
│  │  └─ platform.ts              # 端能力探测（见 §14）
│  ├─ types/                      # 由 shared/ 契约生成，不手写
│  └─ sw.ts                       # 只做 push + 版本提示
├─ index.html
├─ vite.config.ts
└─ tsconfig.json
```

**目录纪律**
- `features/` 之间不得互相 import，只能经 `lib/` 或事件总线通信。防止后期变成一坨。
- `ui/` 里禁止出现任何硬编码色值/字号，只能消费 token。用 stylelint 规则强制。
- `types/` 是生成物，`.gitignore` 掉，构建时从 `shared/` 契约生成。

## 2. 依赖选型

| 用途 | 选 | 为什么是它 | 备选被拒原因 |
|---|---|---|---|
| 构建 | Vite 5 | 定案；快、配置少 | — |
| 框架 | React 18 | 定案 | Svelte 生态小、招人难（用户否） |
| 语言 | TypeScript strict | 契约生成需要 | — |
| 路由 | TanStack Router | 类型安全路由参数；SPA hash/history 均可静态托管 | React Router 类型弱；Next 不能静态 |
| 数据获取 | TanStack Query | 缓存/重试/乐观更新/失效管理齐全，正好承接 SSE 结束后的失效 | SWR 能力不足；手写字面量易错 |
| 服务端状态以外的状态 | Zustand | 极小、无 Provider 地狱 | Redux 太重；Context 有重渲染问题 |
| 样式 | Tailwind 4 + CSS 变量 token | 速度快，token 通过 CSS 变量注入即可换肤 | CSS-in-JS 运行时开销；纯 CSS 手写量大 |
| 长列表 | 自研虚拟列表（基于 `@tanstack/react-virtual`） | 消息流高度不定，需要 `measureElement` 动态高度 | 不虚拟 → 2000 条消息必卡 |
| Markdown | `marked` + `dompurify` | 角色会输出简单格式，必须过 XSS | `react-markdown` 体积大且默认不做 sanitize |
| 动画 | Framer Motion | 手势、共享元素转场 | CSS 手写复杂转场成本高 |
| 图标 | `lucide-react` + 自绘角色图标 | 线性图标无 AI 味 | emoji 图标 = AI 味重灾区 |
| 日期 | `dayjs` | 16KB | date-fns tree-shaking 后差不多但 API 更啰嗦 |

**总量红线**：首屏 JS gzip ≤ **180KB**。超了就把分享图生成器、社区、后台路由全部 `React.lazy` 拆包。

## 3. 设计 token 系统（皮肤的地基）

用户 E2 定案"情感化拟物 + 设计 token + 可卖皮肤"，所以 **token 不是可选优化，是商品载体**。皮肤 = 一份 token 覆盖文件，不是一段 CSS 补丁。

### 3.1 三层结构

```
tier-1  原始值      --c-brand-500: #B8452F
tier-2  语义值      --c-surface-raised, --c-text-primary, --c-accent-warm
tier-3  组件值      --bubble-user-bg, --bubble-ai-bg, --composer-bg
```

**皮肤只覆盖 tier-1 和少量 tier-2**，组件永远只消费 tier-3。这样一份皮肤文件 ≤ 60 行，且不会因组件改版而失效。

### 3.2 token 清单（必做，缺项不许上线）

```css
:root {
  /* 色 */
  --c-paper, --c-paper-warm, --c-ink, --c-ink-soft, --c-ink-faint
  --c-accent, --c-accent-deep, --c-hairline, --c-hairline-strong
  --c-state-danger, --c-state-warn, --c-state-ok

  /* 字 */
  --f-display, --f-body, --f-mono
  --fs-100 … --fs-900        /* 13 档，移动端 clamp() 收口 */
  --lh-tight, --lh-body, --lh-loose
  --ls-quote, --ls-caps

  /* 间距（4px 基准）*/
  --sp-0 … --sp-16

  /* 圆角 */
  --r-sm, --r-md, --r-lg, --r-bubble-user, --r-bubble-ai

  /* 阴影与纸感 */
  --elev-flat, --elev-raise, --elev-float
  --texture-paper-opacity, --texture-grain-url

  /* 动效 */
  --t-fast(120ms), --t-base(220ms), --t-slow(400ms)
  --ease-out-soft, --ease-in-out-soft, --ease-spring
}
```

### 3.3 皮肤运行时

- 皮肤 = `{ id, name, tokens: Record<string,string>, preview, price_tier }`，存库，前端按 `id` 拉取并注入 `<style data-theme>`。
- 切换用 `document.documentElement.setAttribute('data-skin', id)`，**不做 JS 逐个改属性**。
- 校验：皮肤文件加载后跑一次对比度检查（`--c-text-primary` vs `--c-paper` 必须 ≥ 4.5:1），不达标则该皮肤不上架。**卖的东西不能是坏的。**
- 【待定】是否允许用户上传自定义 CSS → 见 HANDOFF 附录 B Q7。若开放，必须走 **CSS `@property` + 白名单变量**，禁止任意选择器，否则等于给 XSS 开门。

## 4. 视觉方向：怎么做掉"AI 味"

抖音同期爆的正是"告别 AI 味前端"。AI 味的具体来源，逐条反着做：

| AI 味特征 | 本项目做法 |
|---|---|
| 深底 + 紫蓝渐变 + 玻璃拟态 | 纸色底（`--c-paper` 偏暖白），**禁用大面积渐变** |
| 圆角 16px 卡片 + 紫色描边 | 分层用不同圆角；气泡圆角不对称（用户侧右下小圆、AI 侧左下小圆） |
| emoji 当图标 | 线性图标 + 自绘角色图标 |
| Inter / 系统默认字体 | 中文正文用**思源宋体或霞鹜文楷类**做角色文本，用户消息用无衬线 —— 两种字体区分"人"和"TA"，这是沉浸感的关键 |
| 一律居中对齐、大标题 | 左对齐为主，标题克制 |
| 生硬 fade-in | 打字机 + 光标 + 消息进入用轻微位移而非缩放 |
| 蓝色链接、紫色按钮 | 主色取纸墨体系里的暖调（朱砂/赭石），**避开科技蓝** |
| "AI 生成"水印满屏 | 机器生成标识必须有（这是产品诚实），但做成**角落细字 + 可展开说明**，不做遮挡式水印 |

**具象化三条**（写进验收）：
1. 截图给不了解项目的人看，第一反应应是"某个人的聊天界面/信纸"，不是"某个 AI 产品"。
2. 角色消息与用户消息在**字体、底色、气泡形状、时间戳位置**四个维度全部不同。
3. 全站不允许出现紫蓝渐变、玻璃模糊背景、发光描边三件套。

## 5. iOS WebApp 适配清单（★生死线）

用户不上架 App Store，**所有 iOS 用户只能"浏览器打开 → 添加到主屏幕"**。这条做不好，等于放弃一半用户。

### 5.1 必须做的元信息
```html
<meta name="apple-mobile-web-app-capable" content="yes">
<meta name="mobile-web-app-capable" content="yes">
<meta name="apple-mobile-web-app-status-bar-style" content="black-translucent">
<meta name="apple-mobile-web-app-title" content="如晤">   <!-- 待定名 -->
<link rel="apple-touch-icon" href="/apple-icons/180.png">  <!-- 152/167/180 三档 -->
<link rel="manifest" href="/manifest.webmanifest">
<meta name="theme-color" content="#F7F3EC">
```
- 图标**必须不透明**（iOS 主屏图标带圆角遮罩，透明底会变黑边）。
- `apple-touch-icon` 用**纯位图、无 maskable 依赖**，iOS Safari 不认 maskable。

### 5.2 视口与高度（iOS 第一大坑）
```css
/* ❌ 100vh 在 iOS Safari 会溢出（包含地址栏高度）*/
/* ✅ 用 dvh，并给不支持的旧版本兜底 */
.app-shell { height: 100dvh; }
@supports not (height: 100dvh) {
  .app-shell { height: -webkit-fill-available; }
}
html, body { margin:0; overscroll-behavior: none; }
```
- **禁止在滚动容器上再用 100vh**。尚贤圈踩过这个坑（"移除 100vh + overflow:hidden 锁死 → 页面自然滚动"），同一个雷。
- 安全区：`padding: env(safe-area-inset-top) env(safe-area-inset-right) env(safe-area-inset-bottom)`，配 `viewport-fit=cover`。

### 5.3 键盘（第二大坑）
iOS 键盘弹出会把整个 visual viewport 顶上去，导致输入框被遮或页面跳动。
- 输入区用 **`position: fixed` + 监听 `visualViewport.resize`** 动态抬升，不用 `:focus` 改布局。
- 键盘弹起时**滚到最新消息**，收起时**回到底部占位**（否则消息区会留一大块空白）。
- 输入框 `font-size` **≥ 16px**，否则 iOS 聚焦时自动放大页面且不会缩回。这是硬约束，token 里 `--fs-input` 不得低于 16px。
- `enterkeyhint="send"`、`autocomplete="off"`、`spellcheck="false"`。
- 中文输入法组合期（composition）内**不得触发发送**，必须监听 `compositionstart/end` 加锁。

### 5.4 滚动与手势
- 消息列表容器 `overscroll-behavior: contain`，防止下拉触发 Safari 的刷新手势。
- 禁用长按弹出系统菜单/图片保存（会打断沉浸）：`-webkit-touch-callout: none`，但**用户消息文本保留可选中复制**（要复制对话去分享）。
- 禁用双击缩放：`touch-action: manipulation`（不用 `user-scalable=no`，那会伤无障碍且有 WCAG 问题）。
- iOS 主屏 WebApp 的返回手势会直接退出应用 → **路由跳转一律 `pushState`，不用 `replaceState` 做 tab 切换**，否则侧滑退出。

### 5.5 渲染与字体
- iOS 中文渲染偏细：正文加 `font-synthesis: none`，字重最低 400 起步，标题用 600 而非 700（iOS 700 会发糊）。
- 自托管字体必须**子集化**（`fonttools pyftsubset` 或 `cn-font-split`），全量中文字体 5-10MB，iOS 上首屏会直接崩。目标：常用 3500 字 + 标点在 **≤ 1.2MB woff2**，并 `font-display: swap`。
- 首屏字体未加载完时用系统字体占位，避免白屏。

### 5.6 存储与生命周期
- iOS 会**在 7 天不活跃后清空 Safari 的 localStorage/IndexedDB**。所以 E1 定"云端权威"是对的，本地只能当渲染缓存，**绝不能当唯一副本**。UI 上不得承诺"本地保存"。
- iOS 主屏 WebApp 切后台约 30 秒即挂起 → 长连接、TTS 播放、流式请求都会中断。缓解：
  - 流式中断 → 服务端已落库，回前台后按 `message_id` 补齐（见 §7.3）
  - 回前台时静默 `refetch` 会话（监听 `visibilitychange`）
- **iOS Web Push 只在已加主屏 + iOS 16.4+ 生效**，且送达率低于原生。文案上不得承诺"随时收到 TA 的消息"。

### 5.7 验收矩阵（写进 `docs/验收清单.md`）
| 环境 | 必验项 |
|---|---|
| iPhone Safari（最新） | 键盘顶起、100dvh、安全区、字体子集、长按行为 |
| iPhone 主屏 WebApp（standalone） | 图标无黑边、无地址栏、返回手势不退出、Push 订阅成功 |
| iPad | 布局不拉伸、分屏可用 |
| iOS 微信内置浏览器 | 分享面板、键盘、`dvh` 兼容 |
| Android Chrome | Push、PWA 安装横幅 |
| Android 国产浏览器（至少 2 款） | 内核旧版 CSS 兼容（`:has`、`dvh`、`inset`） |
| PC Chrome / Edge / Safari | 窗口缩放、键盘快捷键 |

## 6. PWA 与 manifest

### 6.1 生成而非手写
`manifest.webmanifest` 由根目录 `manifest.json` 的 `web` 段生成（构建脚本 `scripts/gen-manifest.mjs`）。**禁止手写版本号**（E4：各端独立但各自有约束 —— 网页侧的约束就是"构建号可追溯且来自单一源"）。

```jsonc
{
  "name": "如晤",
  "short_name": "如晤",
  "id": "/renji-companion/",          // 固定 id，避免改路径时丢安装状态
  "start_url": "/renji-companion/?src=homescreen",
  "scope": "/renji-companion/",
  "display": "standalone",
  "orientation": "portrait",
  "background_color": "#F7F3EC",
  "theme_color": "#F7F3EC",
  "icons": [ /* 192, 512, maskable 各 2 */ ],
  "shortcuts": [
    { "name": "继续上次对话", "url": "/renji-companion/?s=resume" },
    { "name": "新建角色",     "url": "/renji-companion/?a=new" }
  ]
}
```

### 6.2 Service Worker：只做两件事

```ts
// sw.ts —— 本项目的 SW 全文职责被严格限定
self.addEventListener('push', onPush);          // 1. 收推送 → 显示通知
self.addEventListener('notificationclick', onNotifClick);  // 2. 点击 → focus 或 openWindow
self.addEventListener('message', onMessage);    // 3. 收到 SKIP_WAITING → 提示刷新
// ❌ 不写 fetch 事件
// ❌ 不写 cache.addAll / caches.open
// ❌ 不做离线兜底页
```

**为什么不缓存**（B4 定案，理由要写清防止后人"优化"回来）：
1. GitHub Pages 的 CDN 边缘刷新有延迟，缓存版本与线上版本不一致会造成"用户看到旧 UI 但接口是新的"这种最难查的 bug。
2. 本项目所有业务数据都是动态的（对话、余额、权益），缓存它们等于制造脏数据。
3. 尚贤圈已经用血换过这条教训。

**代价**：断网不可用、二次访问不省流量。这是**接受的取舍**，不是待修的缺陷。

### 6.3 更新提示
- 构建时把 `build` 号注入 HTML `<meta name="x-build">`。
- 运行时定时 `fetch('/…/version', {cache:'no-store'})` 比对，发现新构建 → 顶栏出现一条细横幅"有新版本，点这里刷新"，**用户点击才刷新**，绝不自动 reload（会把人正在写的长消息弄没）。

## 7. 对话界面实现要点

### 7.1 布局骨架
```
┌──────────────────────────┐
│ 顶栏（角色名/状态/返回）    │  ← 固定，安全区内边距
├──────────────────────────┤
│                          │
│  消息流（虚拟列表）        │  ← 唯一滚动容器
│                          │
├──────────────────────────┤
│ 建议条（可选，横滑）        │
├──────────────────────────┤
│ 输入区（fixed + 键盘抬升）  │
└──────────────────────────┘
```
- 滚动容器**只有中间这一层**。任何"整页滚动 + 内层滚动"的嵌套都会在 iOS 上出问题。
- 新消息进入时：若用户本来贴底 → 自动跟到底；若用户在往上翻历史 → **不抢滚动**，只在右下角显示"N 条新消息 ↓"。这条不做，用户翻记录会被不断打断，是聊天 UI 最常见的低级错误。

### 7.2 虚拟列表与不定高度
- `@tanstack/react-virtual` + `measureElement`。
- 关键：**从底部开始定位**。聊天列表的"锚点"是最后一条，不是第一条。用 `followOnScroll` + 手动维护 `anchorIndex`。
- 图片/TTS 播放器加载完成会改变高度 → 测高后需 `scrollToOffset` 补偿，防止跳动。
- 历史分页向上加载时，用 `startOffsetIndex` 保持视觉位置不动。

### 7.3 流式渲染
```ts
// lib/sse.ts 要点
- 用 fetch + ReadableStream（不用 EventSource：需要 POST 和自定义头）
- 逐 chunk 解析 SSE 帧；半帧残留要 buffer 住，按 \n\n 切
- delta 累积到 ref，用 rAF 节流 setState（每条 delta 都 setState 会卡）
- 光标：最后一个气泡末尾挂一个 CSS 动画光标
- 断线：收到 [DONE] 前连接断 → 带 message_id 调 resume 接口续接
- 组件卸载：不 abort 请求（服务端在生成，让它落库），只是停止显示
```
- 打字机效果**不要用前端定时器伪造**——真实流式本身就有节奏，伪造反而和实际到达不同步。
- Markdown 在流式中要**容错解析**（未闭合的代码块/加粗先按纯文本渲染，闭合后再格式化），否则会看到 `**` 闪来闪去。

### 7.4 消息气泡
- 用户消息：右对齐、无衬线、纸墨暖底、右下角小圆。
- 角色消息：左对齐、衬线/楷体、更浅底、左下角小圆、可选"信纸纹理"（`--texture-*`）。
- 时间戳：按间隔规则显示（相邻 < 5 分钟不重复显示），不每条都挂时间。
- 长按/右键菜单：复制、引用、朗读（TTS）、删除、举报。
- 出戏/重生成对用户不可见（P4 定案"静默重生成"）。

## 8. Web Push 实现

```ts
// 1. 注册 SW 后取 subscription
const sub = await reg.pushManager.subscribe({
  userVisibleOnly: true,
  applicationServerKey: urlBase64ToUint8Array(VAPID_PUBLIC_KEY),
});
// 2. 上报服务端（含 platform 与 UA，用于区分 iOS/PC 送达策略）
await supabase.functions.invoke('push', { body: { action:'register', subscription: sub } });
// 3. 权限请求时机：★不要在首次进入就弹权限框。
//    必须在"用户已经完成第一次对话"之后，或以"打开时补发"作为替代话术引导。
```
- iOS 的 Push 必须在 **standalone（已加主屏）** 下才能订阅；Safari 标签页里 `pushManager` 会直接抛错 → 探测到 iOS 非 standalone 时，引导"添加到主屏幕"，而不是报错。
- 通知点击 → `clients.matchAll({type:'window'})`，有则 `focus()` + postMessage 跳转，无则 `openWindow()`。
- 通知必须带 `tag`，同一角色的多条主动消息**合并成一条**（否则用户被刷屏，直接关权限，永久失去通道）。

## 9. 状态与数据获取分层

| 层 | 放什么 | 工具 |
|---|---|---|
| 服务端状态 | 会话、消息页、角色、余额、权益、社区 | TanStack Query（唯一真源） |
| 客户端持久 | 当前皮肤、输入草稿、滚动位置、引导已读 | Zustand + persist（localStorage） |
| 瞬时 | 流式 buffer、组合输入锁、菜单开合 | 组件内 state / ref |

**规则**
- 任何"从服务器来的数据"不得复制进 Zustand。双写必然漂移。
- SSE 结束 → `queryClient.invalidateQueries(['messages', session_id])`，不手动往缓存塞 AI 消息（服务端才是真源，且要拿 usage）。
- 乐观更新只用于**用户自己发的消息**（立即上屏，失败标红可重试）。

## 10. 性能预算（超了就是 bug，不是优化项）

| 指标 | 预算 | 怎么测 |
|---|---|---|
| 首屏 JS（gzip） | ≤ 180KB | `vite build` + `rollup-plugin-visualizer` |
| 首屏 CSS | ≤ 40KB | 同上 |
| 字体总量 | ≤ 1.2MB（子集化后） | 构建产物检查 |
| FCP（4G 模拟） | ≤ 1.8s | Lighthouse |
| TTI | ≤ 3.0s | Lighthouse |
| 消息列表 2000 条滚动 | 不掉帧（≥ 55fps） | Performance 面板 |
| 单条消息渲染 | ≤ 8ms | React Profiler |
| 输入区响应（打字延迟） | ≤ 16ms | 手测 + Profiler |

**手段**
- 路由级 `React.lazy`；社区、分享图生成器、后台一律异步。
- 图片一律 WebP/AVIF + `loading="lazy"` + 显式宽高（防 CLS）。
- 长列表虚拟化（§7.2）。
- 角色头像/立绘用 CDN 变换参数出多尺寸，不下载原图。
- 禁止在渲染函数里做 token 计数、日期格式化、Markdown 解析 → 全部 `useMemo` 或预计算。

## 11. 输入区细节（体验成败都在这里）

- 多行自动增高，上限 6 行后内部滚动。
- 发送键状态：空 → 禁用；组合输入中 → 禁用；请求中 → 变"停止"（可中断显示，服务端继续）。
- `Shift+Enter` 换行 / `Enter` 发送（PC）；移动端 `enterkeyhint="send"`，换行走"换行"小按钮。
- 草稿按 `session_id` 分别存，切会话不串。
- 粘贴图片 → 直接进附件区（表情包/立绘上传同一条路径）。
- 输入长度接近档位上限时给软提示，不硬截断。
- **禁止任何"AI 帮你写"的输入框增强** —— 这个产品的核心是"我在和 TA 说话"，输入框里出现辅助生成会立刻破坏关系感（也最容易被误认为 AI 味）。

## 12. PC 端专项

- 三栏：左会话列表 / 中消息流 / 右角色与记忆详情。窄屏（< 1100px）自动降为两栏，< 760px 单栏。
- 键盘快捷键：`⌘/Ctrl+K` 切会话、`Esc` 关面板、`⌘↑` 编辑上一条重发。
- 拖拽上传表情包/立绘。
- 消息区最大宽度 `68ch`，超宽屏不拉满（拉满阅读体验极差）。
- 窗口标题在有未读主动消息时闪烁提示（配合系统通知）。

## 13. 无障碍（不是可选项）

- 全部交互元素可键盘到达，焦点环不隐藏（用 `:focus-visible` 自定义，别 `outline:none` 了事）。
- 消息流用 `role="log"` + `aria-live="polite"`，但**流式 delta 不得逐字播报**（读屏会被念疯）→ 只在 `done` 时更新 live region。
- 对比度 ≥ 4.5:1（皮肤上架前自动校验，见 §3.3）。
- 尊重 `prefers-reduced-motion`：关掉打字机光标动画、气泡入场位移、纸张纹理动效。
- 字号跟随系统：`--fs-*` 用 `clamp()` + `rem`，禁止 `px` 锁死正文。

## 15. 构建与部署（GitHub Pages）

```
vite build --base=/renji-companion/
```
- `base` 必须等于子路径，否则资源 404。`id`/`scope`/`start_url` 三处路径必须一致（§6.1）。
- SPA 刷新 404 问题：Pages 不支持 rewrite → **用 hash 路由兜底**或加 `404.html` 转发脚本。推荐 `404.html` 里写一段把路径与 query 转成 hash 再跳 `index.html` 的标准 hack。
- CI：`push → build → deploy-pages`（官方 action），构建产物不入库。
- 【必做】`robots.txt` 与 `X-Robots-Tag` 决策：要不要被搜到？影响抖音搜索卡位（H4 的 SEO 选项），【待定】。
- 预览环境：每个 PR 一个 Pages branch preview，方便真机扫码验收。
