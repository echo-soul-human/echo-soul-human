## 10 · 依赖关系要点（为什么是这个顺序）

1. **P2 在 P3 之前**：RAG 召回条数直接决定 token 消耗。顺序反了，P3 会把 P2 定好的成本模型吃掉。
2. **P4 在 P5 之前**："不出戏"是产品成立前提，比多端覆盖重要。多端铺开了但角色会跳戏，等于给差评铺渠道。
3. **P6 在所有体验之后**：**首次对话完成率没达标之前开始收费，等于花钱买差评。**
4. **1-4 / 1-6 / 2-6 / 5-10 这四道测试与 CI 防线必须早于对应功能完成**，它们是"防止后期被无意破坏"的机制，不是收尾工作。
5. **6-1（爱发电 API 核实）是 P6 的阻塞项**，建议提前到 P0 并行轨去做——它不通，整个归因方案要换。
